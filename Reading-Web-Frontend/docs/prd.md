# Reading-Web-Frontend 学生阅读前端网站
## 1. 概述
### 定位
面向初一学生的纯阅读前端站点，**只读应用**，仅通过Supabase anon密钥读取articles表，无数据库写入权限；收藏功能保存在浏览器localStorage。
### 依赖
Supabase anon只读API
### 目标
干净、低干扰的双语泛读页面；支持视图切换、段落联动高亮、日历查阅、多维度筛选。

## 2. 功能需求
### 2.1 日历导航组件
- 日历组件支持【收起 / 展开】，默认收起，不干扰阅读主视图
- 选择日期，加载当日发布、is_published=true 的文章列表
- 只展示有文章的日期标记

### 2.2 筛选面板
- 筛选面板支持【收起 / 展开】
- 筛选项：主题、文体、难度L1/L2/L3，支持多选过滤
- 文章卡片展示彩色标签，标签颜色取自color_tag字段

### 2.3 文章列表卡片
卡片信息：英文标题、中文标题、主题标签、难度标签、文体标签、发布日期

### 2.3.1 首屏时效与按日期按需加载
- 文章按发布日期倒序展示（同日按 sort 升序），最新一天排在最前
- 首屏只请求「最新一天」的文章分片 + 一个极小的日期索引（`articles-index.json`），
  不一次性下载全量文章，降低首屏加载体积与时延
- 用户向下滚动到列表底部时，才逐日加载更早日期的分片（`articles-<date>.json`），
  追加到列表末尾；已加载的日期不重复请求。首屏首次渲染（尚未滚动）绝不自动加载，
  严格保证首屏只请求今日数据
- 当已加载内容不足一屏、页面无滚动空间时，列表底部提供「加载更多」按钮让用户主动加载，
  作为滚动触发的兜底（此时"向下滚动"无从触发）
- 日历的日期标记读完整索引（所有有文章的日期都可见），即使对应分片尚未加载；
  用户从日历跳到未加载日期时按需补拉该日分片
- 筛选在「已加载文章」范围内进行；无筛选的浏览态才启用滚动自动加载，
  选中日期或开启筛选时不自动续加载
- 构建期产物：`articles.json`（全量，供阅读页深链兜底）、`articles-index.json`、
  `articles-<date>.json`（每日分片）；CI 校验三者齐全才发布

### 2.4 阅读详情页（核心交互）
1. 排版固定一套布局，不切换左右/上下对照版式
2. 视图切换按钮三档：【仅英文】｜【仅中文】｜【双语同显】
3. 段落绑定：english_paras、chinese_paras按数组下标一一配对
4. 联动高亮：鼠标选中一侧段落文本，自动高亮绑定的另一侧对应段落
5. 无内置生词标注、无点击查词弹窗
6. 正文无练习题、无解析、无思考题
7. **读后思考折叠区**：正文段落之后、页脚之前，标题「💭 读后思考」，默认折叠，
   展开显示 `reflection_en` + `reflection_cn` 两行（一句引导语，不是题目）。
   文章没有这两个字段（存量文章 / 常青文章）时整块不渲染。
   快照 `articles.json` 与 Supabase SELECT 都必须带上这两列，否则国内学生首屏看不到

### 2.5 收藏功能
- 收藏状态存储在浏览器 localStorage，不上传云端
- 独立收藏页面：展示所有收藏文章，支持取消收藏
- 换浏览器、清空缓存后收藏数据丢失

### 2.6 响应式适配
同时适配电脑端、手机端浏览。

## 3. 输入输出
- 输入：从Supabase articles拉取已发布文章数据
- 输出：页面渲染；收藏标记保存在前端本地存储

## 4. 非功能需求
1. 轻量化，加载速度优先；首屏只加载最新一天数据，更早数据滚动按需加载（§2.3.1）
2. 只读，前端代码不包含任何数据库写入逻辑
3. 界面简洁，减少视觉干扰，适合长时间阅读
4. 配色统一，标签颜色与后台配置一致

## 5. 边界说明（不做）
- ❌ 不调用搜索、爬虫、素材采集能力
- ❌ 无法访问 source_log 素材表
- ❌ 没有后台录入、素材管理页面
- ❌ 不做打卡、阅读时长、阅读记录云端存储
